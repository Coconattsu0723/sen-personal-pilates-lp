# SEN PERSONAL PILATES｜Decisions Log

## この文書の役割

企画・ブランド・デザイン・素材・実装方針について、「何を決めたか」「なぜそうしたか」「何を採用しなかったか」を簡潔に残す判断ログ。

## 1. 商材

### 採用

パーソナルピラティスの1ページLP。

### 理由

- 体験予約という明確なCVを設計できる
- 写真、図解、料金、FAQを自然に構成できる
- 共感から行動までの情報設計を見せられる
- HTML / CSS / JavaScriptの実装力も示しやすい

### 非採用

- CVが曖昧なブランド紹介だけのサイト
- 情報設計よりビジュアル展示が中心になる構成

## 2. ターゲット

### 採用

28〜35歳程度の、デスクワーク中心の働く女性。

### 理由

- 姿勢、肩・背中まわり、運動不足という課題がサービスと自然につながる
- 「運動したいが何が合うか分からない」という中心課題を明確にできる
- 初心者向けマンツーマンの価値を伝えやすい

### 非採用

- 競技志向や高強度トレーニングを求める層を中心にすること
- 女性専用サービスとして断定すること

## 3. 訴求

### 採用

```text
自分の身体を知る → 整える → 続ける
```

### 理由

- ターゲットの「何が合うか分からない」という課題に応えられる
- SENの丁寧で信頼できる人格と一致する
- 姿勢チェック、個別プラン、継続を一つの体験として説明できる

### 非採用

- ダイエット・痩身中心
- 短期間の劇的変化
- 追い込みや強い美容訴求

## 4. CV

### 採用

**姿勢チェック付き初回パーソナル体験レッスン予約**

### 理由

- 単なる体験よりSEN固有の価値が明確になる
- 「まず知る」というブランドコンセプトから予約へ自然につながる
- 初心者が最初の一歩を理解しやすい

### 非採用

- 内容が分からない「体験予約」だけの訴求
- 入会を強く迫るCTA

## 5. ブランド名

### 採用

**SEN** / **SEN PERSONAL PILATES**

### 理由

- 「線」「軸」「姿勢」を連想できる
- 短く、ミニマルで知的な印象を作りやすい
- ブランドコンセプトと姿勢チェックの両方につながる

### 非採用

- 美容サロンやスポーツジムを強く連想する名称
- 長く説明的な名称

## 6. ロゴ

### 採用

SENを主役にし、その下にPERSONAL PILATESを置く2段ワードマークのB案。

### 理由

- タイポグラフィ主体で静か、上品、ミニマルな印象を作れる
- ブランド名を明確に見せられる
- 他のビジュアルを邪魔しない

### 非採用

- 女性の身体をS字にしたシンボル
- ヨガポーズ、蓮、葉、ハート、羽
- 美容サロン風、スポーツジム風、医療機関風の意匠

## 7. デザイン

### 採用

**Natural Calm**

コンセプト：**身体と向き合う、静かな余白。**

### 理由

- SENの「静か・丁寧・信頼できる」と一致する
- 自然光、余白、タイポグラフィを活かせる
- 初心者が緊張しにくい印象を作れる

### 非採用

- 強いスポーツ感
- 高級ホテルのような豪華さ
- かわいすぎる淡色デザイン
- 医療機関のような無機質さ

## 8. LPの心理設計

### 採用

```text
共感 → 理解 → 信頼 → 行動
```

### 理由

- ターゲットの悩みから始め、考え方とサービスを理解してもらえる
- Studio、Trainer、体験内容、料金で段階的に不安を減らせる
- 強い煽りを使わず予約へ導ける

### 非採用

- ページ冒頭から料金や入会を強く押し出す構成
- 写真だけでサービス内容を説明する構成

## 9. 写真方針の変更

### 初期案

人物写真を12〜16点程度使用する想定。

### 最終採用

人物写真を多用せず、正式写真を5点に限定する。

- Hero
- Studio Main
- Studio Detail 01
- Studio Detail 02
- Trainer Portrait

### 理由

- SENの静かな世界観を維持する
- 写真過多による広告感を避ける
- 情報設計、余白、タイポグラフィを見せる
- 悩みや特徴はイラスト・アイコン・図解の方が整理しやすい

### 非採用

- 使える場所すべてに人物写真を入れること
- Voice用の顔写真
- 広告モデル風のポーズや痩身訴求

## 10. アイコン方向の変更

### 初期案

細く、ミニマルさを強くした線画。

### 最終採用

少しポップでやわらかい、大人の女性向け線画。

### 理由

- 初期案は単調で硬い印象があった
- 初心者が感じる緊張を和らげられる
- 写真を増やさず悩みや特徴を伝えられる

### 維持する制約

- 子どもっぽくしない
- カラフルにしすぎない
- 3D、グラデーション、強い影を使わない

## 11. 姿勢チェック図解

### 初期案

複数のアイコンや点線パーツを含む、情報量の多い図解。

### 最終採用

正面・側面の人物を用い、頭・肩・骨盤・全体バランスへ情報を絞る。

### 理由

- 一目で確認観点を理解できる
- LP内で読みやすい
- 医学的な診断図に見えることを避けられる

### 非採用

- 重複アイコン
- 過剰な点線パーツ
- 医療診断を想起させる詳細表現

## 12. 正式素材

### 採用

正式素材16点を採用済み。

- ロゴ：1点
- 写真：5点
- お悩みアイコン：5点
- 特徴アイコン：4点
- 姿勢チェック図解：1点

### 理由

- 15セクションの主要なブランド表現を過不足なく支えられる
- 写真を増やさず、用途ごとの表現を分担できる
- ファイル名と用途を固定し、実装時の取り違えを防げる

### 非採用

- 同用途の重複素材
- ダウンロード時の仮ファイル名
- 一般UIアイコンのPNG化

## 13. 一般UIアイコン

### 採用

Menu / Close / Arrow / FAQ ＋・− / Check / Calendarは、インラインSVGまたはCSSで実装する方針。

### 理由

- 状態変化や色変更へ対応しやすい
- 一般UIをブランド固有画像として管理する必要がない
- アクセシビリティ上の意味付けを実装側で管理しやすい

### 未確定

外部アイコンライブラリを使用するか。

## 14. 実装技術

### 採用

- HTML
- CSS
- Vanilla JavaScript
- モバイルファースト

### 理由

- ポートフォリオとして基本的な実装力を示せる
- 1ページLPに不要なフレームワーク依存を増やさない
- JavaScriptなしでも主要情報を読める構造にできる

### 非採用

- 現段階でのフレームワーク導入
- 不要なアニメーションライブラリ
- 実データを送信するフォーム

## 15. Headerと固定CTAの役割分離

### 採用

- PC Header：SENロゴ＋ABOUT / LESSON / STUDIO / TRAINER / PRICE / FAQ
- PC Header内にはCTAを配置しない
- 初回体験予約CTAは画面右端の縦型固定CTAとして分離する
- SP / Tabletはロゴ＋ハンバーガーメニューとし、メニュー内にも予約CTAを配置する
- SP / Tabletの固定CTAは小型・横書きとする

```text
Header＝サイト内ナビゲーション
固定CTA＝コンバージョン導線
```

### 理由

- Headerをシンプルに保つ
- SENの静かな世界観と余白感を維持する
- Headerを過密にせず、CV導線は常時確保する

### 非採用

- PC Header内へ予約CTAを組み込むこと
- 広告バナーのように派手な固定CTA
- 強い影や過度な装飾

## 16. Voice設計

### 採用

顔写真を使わず、正式本文を持つ3名のVoiceを掲載する。

- 身体を知る価値：29歳 / IT企業勤務
- 初心者でも続けやすいこと：32歳 / 事務職
- 仕事帰り・プライベート空間・通いやすさ：35歳 / 営業職

### 理由

- SENの主要価値を異なる利用者視点で補強できる
- 写真を増やさず、テキストで信頼を形成できる
- ターゲットが自分に近い状況を見つけやすい

### 非採用

- 劇的なBefore / After
- 痩身成果や短期間の変化を強調するVoice
- Voice用の顔写真

## 17. 予約フォーム設計

### 採用

初回予約に必要な8項目だけを取得する。

1. お名前
2. メールアドレス
3. 電話番号
4. 希望日
5. 希望時間
6. ピラティス経験
7. 気になること
8. 同意チェック

実際の外部送信は行わず、Vanilla JavaScriptでページ内にデモ完了表示を出す。

### 理由

- 必要以上の個人・身体情報を取得しない
- 初回予約時の心理的・入力負担を抑える
- SENの「まず気軽に自分の身体を知る」というコンセプトと一致する
- フォーム離脱を防ぎやすい

### 非採用

- 住所、生年月日、身長、体重、病歴、詳細な健康状態の取得
- 外部サービスへの実送信
- 内容が曖昧な「送信する」ボタン

## 18. ブレークポイント設計

### 採用

モバイルファーストで、レイアウト構造が変わる以下の2段階を基本とする。

```text
768px
1024px
```

- SP：〜767px
- Tablet：768〜1023px
- PC：1024px〜

### 理由

- 確認幅とレイアウト切替地点を分離できる
- CSSの複雑化を抑えられる
- TabletへPCレイアウトを無理に縮小せずに済む
- 1366px・1440pxではPCレイアウトの安定性確認に集中できる

### 非採用

- 375 / 390 / 768 / 1024 / 1366 / 1440の各確認幅ごとにmedia queryを作ること
- 必要性のない細かなブレークポイント追加
