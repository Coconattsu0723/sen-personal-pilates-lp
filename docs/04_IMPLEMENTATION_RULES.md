# SEN PERSONAL PILATES｜Implementation Rules

## この文書の役割

Codexが後工程でHTML / CSS / JavaScriptを実装するときのルール。現時点では実装を行わず、この文書を実装判断の正本とする。

## 基本方針

- HTML / CSS / Vanilla JavaScript
- 1ページLP
- モバイルファースト
- SP基準375px
- セマンティックHTML
- Heroだけに`h1`を使用する
- 主要セクションは`h2`を使用する
- JavaScriptが無効でも主要情報を読めるようにする
- JavaScriptは補助的なインタラクションに限定する
- 外部送信を行わないポートフォリオ用ダミーフォームとする
- 仕様にない情報・機能・装飾を実装都合で追加しない

## 表示確認幅と確認順

```text
375
↓
390

768
↓
1024
↓
1366

```

- 単位はpx
- 375pxを基準に実装する
- SP：〜767px
- Tablet：768〜1023px
- PC：1024px〜
- 大きな切り替えは`768px`と`1024px`の2段階を基本とする
- 確認幅ごとにmedia queryを作らない
- 必要性が明確でない限りブレークポイントを増やさない
- 中間幅でもレイアウト破綻や横スクロールがないことを確認する

基本media query：

```css
@media (min-width: 768px) {
}

@media (min-width: 1024px) {
}
```

## HTML

- `header`、`main`、`section`、`footer`等を意味に沿って使用する
- ナビゲーションには`nav`を使用する
- Heroの主要見出しだけを`h1`とする
- 見出し階層を見た目だけで決めない
- CTAは遷移か送信かに応じて`a`と`button`を使い分ける
- 画像は装飾か情報かを判断し、適切な`alt`を設定する
- 料金は見た目だけでなく、読み上げても関係が分かる構造にする
- FAQはJavaScriptなしでも質問と回答へアクセスできる構造を優先する
- 意味のない`div`やARIA属性を増やさない

## Header・固定CTA

### PC（1024px〜）

- HeaderはSENロゴとABOUT / LESSON / STUDIO / TRAINER / PRICE / FAQだけで構成する
- Header内へCTAを配置しない
- 初回体験予約CTAをHeaderと分離し、画面右端へ縦型で固定する
- 固定CTA文言は「初回体験を予約する」とする
- Headerをサイト内ナビゲーション、固定CTAをコンバージョン導線として役割分担する

### SP / Tablet（〜1023px）

- HeaderはSENロゴ＋ハンバーガーメニューとする
- メニュー内へ正式ナビゲーション6項目と「初回体験を予約する」を配置する
- 初回体験予約CTAは、画面右下などへ小型・横書きで固定する
- 固定CTAがメニュー、フォーム、主要コンテンツの操作を妨げないようにする

## CSS

- モバイルファーストで記述する
- 色、フォント、余白、コンテナ幅等の共通値はCSS Custom Propertiesを検討する
- 共通コンポーネントと固有セクションのスタイルを区別する
- 不要な`!important`を避ける
- 強い`box-shadow`を使用しない
- 画像に固定高さを多用しない
- `object-fit`と`aspect-ratio`を適切に使用する
- レイアウト目的で不要な絶対配置を多用しない
- 横スクロールを隠して問題を覆わない
- フォーカス表示を消さない
- クラス命名規則とCSSのファイル分割は実装開始前に確認する
- 768px・1024px以外のmedia queryは、構造上必要な理由がある場合だけ追加する
- PCコンテナは`max-width: 1120〜1200px`程度を目安にし、実装レビューで最終調整する
- SPの左右余白は約24px、768pxでは約32pxを目安とする
- 1366px・1440pxでは新しい構造へ切り替えず、PCレイアウトの安定性を確認する

## 画像

- `03_IMAGE_ASSETS.md`の実在パスを使用する
- 正式原本を上書き編集しない
- CSSによる表示上のトリミングは、主題を損なわない範囲で行う
- 下層の写真は必要に応じて`loading="lazy"`を検討する
- Hero画像の読み込み優先度は実装時に検討する
- PNGから別形式への変換や軽量化派生ファイルの作成は、公開前に方針を確認してから行う
- `alt`はファイル名ではなく、セクション内の役割を基準にする

## JavaScript

予定する機能は最低限に限定する。

- FAQアコーディオン
- SPメニュー
- 予約フォームの簡易バリデーション
- ダミー送信
- 送信完了表示

### JavaScriptの制約

- 不要なアニメーションを追加しない
- 主要本文をJavaScriptで後から生成しない
- 初期表示に必要な情報をJavaScript依存にしない
- SPメニューはEscapeで閉じられるようにする
- メニューを閉じた後のフォーカス復帰を考慮する
- FAQはキーボードで操作できるようにする
- `aria-expanded`と`aria-controls`を状態に合わせて更新する
- `prefers-reduced-motion`を尊重する
- 外部APIや実送信処理を追加しない

## 予約フォーム

最終CV：**姿勢チェック付き初回パーソナル体験レッスン予約**

### 正式項目

| # | 項目 | 必須 | 実装方針 |
|---:|---|---|---|
| 1 | お名前 | 必須 | テキスト入力 |
| 2 | メールアドレス | 必須 | `type="email"` |
| 3 | 電話番号 | 必須 | 簡易形式チェック |
| 4 | 希望日 | 必須 | 入力UIは実装時に決定 |
| 5 | 希望時間 | 必須 | 入力UIは実装時に決定 |
| 6 | ピラティス経験 | 必須 | 3つの正式選択肢を使用 |
| 7 | 気になること | 任意 | `textarea` |
| 8 | 同意チェック | 必須 | プライバシーポリシーはダミーリンク |

ピラティス経験の正式選択肢：

- 初めて
- 1〜5回程度
- 継続して経験あり

「気になること」案内文：

> 姿勢や身体について、気になっていることがあればご記入ください。

プレースホルダー例：

> デスクワーク後の肩まわりが気になる、姿勢を確認してみたい など

同意文：

> 入力内容とプライバシーポリシーを確認し、予約申し込みに同意します。

送信ボタン：

> この内容で体験予約を申し込む

「送信する」だけの文言は使用しない。

### フォームルール

- 外部送信を行わないダミーフォームとする
- JavaScript無効時に実送信されないよう設計する
- 各入力に省略しない`label`を用意する
- 必須・任意を色だけで示さない
- エラー内容を入力欄と関連付ける
- エラー時に入力内容を不必要に消さない
- ダミー送信であることをユーザーに明示する
- 実際の送信先、保存先、通知先を推測しない
- HTML標準機能とJavaScriptを併用する
- HTML側で`required`、`type="email"`、適切な`label`を使用する
- 必須項目、メール形式、電話番号の簡易チェック、同意チェックを最低限検証する
- JavaScriptだけにバリデーションを依存させない
- Vanilla JavaScriptでデフォルト送信を止め、ページ内へ完了表示を出す

### 送信後の完了表示

見出し：

> ご予約ありがとうございます。

補助文：

> 入力いただいた内容を確認のうえ、予約日時についてご案内する想定のデモフォームです。

注記：

> このフォームはポートフォリオ用のダミーフォームです。実際の予約・送信は行われません。

### 収集しない情報

- 住所
- 生年月日
- 身長
- 体重
- 病歴
- 詳細な健康状態

初回予約時の心理的・入力負担を増やさないため、取得しない。

## Accessibility

最低限、以下を確認する。

- 適切な見出し構造
- 文脈に合う`alt`
- `aria-expanded`
- `aria-controls`
- `aria-label`は可視ラベルが使えない場合など必要なときだけ使用
- キーボード操作
- EscapeでSPメニューを閉じる
- FAQのキーボード操作
- 見やすいFocus表示
- 色だけで意味を伝えない
- Form labelを省略しない
- エラーメッセージを読み上げ可能にする
- 文字と背景のコントラスト
- タップ領域の大きさ
- ズーム時と文字拡大時の破綻
- 可能な範囲で動きを抑える設定への対応

## 一般UIアイコン

Menu / Close / Arrow / FAQ ＋・− / Check / Calendarは、正式画像素材を新規作成せず、インラインSVGまたはCSSを候補とする。

- 意味のあるアイコンには適切なラベルを付ける
- 装飾アイコンは読み上げ対象から外す
- 外部アイコンライブラリの採用は未確定

## Performance

- 不要なライブラリを追加しない
- 画像寸法を指定してレイアウトシフトを抑える
- 下層画像の遅延読み込みを検討する
- Webフォントのウェイト数を必要最小限にする
- JavaScriptの実行量を抑える
- 画像軽量化は原本を保護する方針で行う
